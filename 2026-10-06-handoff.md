# Device handoff — started 2026-10-06, current as of 2026-10-10

Current state and next steps are in **Where things stand** below; the dated updates after **Access** are the history.

## Goal
Build a voice-first Android device with a privileged agent and cloud AI inference. No calls or SMS needed. The RAVOZ V1 is throwaway hardware; its touchscreen is already unreliable.

## What happened
- The RAVOZ V1 runs stock Android 12. Its bootloader was locked. After a `fastboot reboot`, it stalled on the RAVOZ logo; pressing Power brought up a “Can't load Android system” recovery screen. **Factory data reset** got it booting again. The health-library warning on that screen did not identify the cause.
- Enabled **OEM unlocking** and USB debugging again after the reset. Fastboot reported `unlock_ability = 16777216` (rather than the usual `1`). The unlock succeeded after confirming with **Volume Up** on the phone. `fastboot getvar unlocked` returned `yes`; Android reported `ro.boot.flash.locked=0`.
- Booted the **non-GMS Android 13 ARM64 GSI** (`TQ3A.230805.001.A3`) through **DSU Loader**. This is a temporary system; stock Android 12 remains available through the DSU notification's **Restart** action. No OS image was flashed.
- On the GSI, ADB, Wi-Fi/internet, screen sleep/wake, battery reporting and charging worked. Android detected the touchscreen, speaker, mic and two cameras. *(Mic and speaker were tested and work: see the 2026-10-10 afternoon update.)* DSU's temporary `/data` is about 1.9 GB.

## Device facts (read over ADB on the DSU, 2026-10-09)
- SoC **MediaTek MT6761** (Helio A22, `MT6761V/WBB`), 4× Cortex-A53; RAM **2.8 GB** (~1.7 GB available while idle); screen 720×1600 @ 320 dpi.
- Kernel 4.19.191. Vendor partition is Android 12, **VNDK 31**. `ro.build.ab_update=true` (A/B) and `ro.boot.dynamic_partitions=true` (super partition); this is a standard Treble layout.
- **Virtual A/B** (`ro.virtual_ab.enabled=true`), current slot `_a`, vendor not VNDK-lite. Vendor fingerprint `RAVOZ/RAVOZ_V1_3_64/RAVOZ_V1_3_64:12/SP1A.210812.016/1692877872:user/release-keys` (3 GB / 64 GB variant).
- Running GSI: `Android/aosp_arm64/generic_arm64:13/TQ3A.230805.001.A3/10454027:user/release-keys`. It is a **`user`** build, so `adb root`, `adb remount`, `tinycap` and `tinyplay` are unavailable. *(That was the DSU. The phone now runs TrebleDroid `userdebug`, flashed to `system_a`; see Phase 1.)*
- Bootloader unlocked (`ro.boot.flash.locked=0`). The DSU had been up for about 68 h without a reboot.
- Because the SoC is MediaTek, the stock restore tool is **SP Flash Tool** (needs a scatter file), and BROM/`mtkclient` recovery is likely available. Neither has been verified yet.
- Stock Android 12 fingerprint and `fastboot getvar all` output have **not** been recorded yet.

## Where things stand (2026-10-10)
**Working on the phone** (repo: https://github.com/code-akram/or1, `main`; details in `app/README.md`):
- `com.or1.agent` is the HOME app: a chat composer is the whole UI. The agent is Claude Haiku 5.5 (adaptive thinking, medium effort) through the Anthropic Java SDK, with replies streamed into the chat and prompt caching at a 1-hour TTL. Each message carries the local time.
- 12 tools: screen, act, open, device, clock, calendar, contacts, notifications, apps, shell (root through phh-su; `content query` runs as the app), memory, routines.
- Apps the agent drives run on a hidden, secure work display (live thumbnail, full-screen viewer, take over, bring to front). Apps there are muted while a request runs.
- Approvals: reads and navigation run freely; changes ask (Allow / Always / Deny). `open` with a URI and, in routines, memory writes also ask (planted-instruction hardening).
- Routines (time or notification triggered) run in their own thread with a Routines screen (edit, remove, revoke Always answers, Continue in chat); approvals also go out as notifications with buttons. Exact alarms are re-armed on boot; a run waits for the network (waking the screen if needed) and retries once.
- A chat idle for over an hour starts afresh on the next message; each chat has its own transcript under past chats. Request gaps are logged for checking the cache TTL.
- Calendar through Etar (F-Droid) with a local "Phone" calendar; the broken AOSP Calendar is disabled.

**Quality:** the on-device eval (`proto`, 30 tasks incl. three prompt-injection tests) is checked automatically and passes 30/30, about $0.0003 per task, median 3 s. CI runs 18 JVM unit tests (app) and 12 pytest tests (proto) on every push.

**Phone state at handoff:** clean (no routines, test contacts, events, alarms or test notifications; memory holds one note: "User prefers short replies and dark mode."), DND off, adbd not root, gap log empty so it reflects real use. Etar installed and allowlisted; AOSP Calendar disabled; Magisk app installed but inactive.

**Day-to-day commands:** build `cd app && ./gradlew :agent:assembleDebug` (JDK 17), install and set up `app/scripts/provision.sh`, unit tests `./gradlew :agent:testDebugUnitTest` and `cd proto && uv run pytest`, eval `cd proto && uv run or1-eval --target phone --auto-approve --no-judge`, trends `uv run or1-eval-report`, cache-gap check `uv run or1-gaps`.

**Known limits:** Wi-Fi sometimes doesn't rejoin with the screen off (routines wake the screen to work around it). After a reboot the phone once dropped off the Mac's ADB server; restarting the SSH tunnel brought it back. Force-stopping the agent disables its accessibility service until it's re-enabled. Voice input and output aren't wired up.

**Next steps:**
1. Voice, once the ElevenLabs startup application is approved (mic and speaker are verified). Before that: check whether the GSI has an Android TTS engine (spoken replies as a stopgap), and mic-button groundwork (recording, silence detection, level meter).
2. After a few days of real use, run `uv run or1-gaps` to confirm the 1-hour cache TTL fits (see the night update).
3. Repo landing page: screenshots, architecture overview, a first tagged release.

[OpenPhone](https://github.com/secondly-com/OpenPhone) is a useful system-agent reference, but its current ROM targets Pixel 9a on Android 16; it cannot be flashed onto this phone. Its own code is source-available **for non-commercial use**, not unrestricted open source. A Pixel 9a would be the direct route to testing that full ROM, but is not required for this RAVOZ experiment.

## Access
- Mac session: `pi-mac` (Pi remote control). USB device serial: `RAV1022V1000265`.
- Mac forwards its ADB server to this host with:
  ```sh
  ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
    -R 127.0.0.1:5038:127.0.0.1:5037 archlinux
  ```
- Here, use `/home/akram/.local/share/android/platform-tools/adb -P 5038 devices -l`. **Fastboot runs on the Mac**, not over this ADB tunnel.
- Last confirmed state (2026-10-10): TrebleDroid Android 13 (`userdebug`) on `system_a`, ADB authorized, visible through the tunnel on port 5038.
- **The Mac ADB server also has the user's OnePlus 10 Pro attached (serial `d41317c3`, NE2211). Do not touch it.** Always pass `-s RAV1022V1000265`. Never run untargeted ADB commands or server-wide ones (`kill-server`, `reconnect`, `usb`, `tcpip`) on port 5038. If the tunnel is down, do not run `adb -P 5038` here: it would start a local server on that port and block the tunnel.
